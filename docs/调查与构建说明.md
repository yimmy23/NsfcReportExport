# NsfcReportExport 调查与构建说明

这份说明只覆盖 `yimmy23/NsfcReportExport` 在 2026-11-25 的源码阅读、离线构建和测试。它不部署网站，不下载国自然报告，也不给上游 `ejfkdev/NsfcReportExport` 提变更。

仓库没有 `LICENSE` 文件。GitHub API 返回的 `license` 也是 `null`。这里不补许可证。

## 结论

不能用这个仓库自部署 `https://nsfc.ejfkdev.com/`。仓库里没有该网站的程序。可以本地加载的是 Chrome 扩展。

请只安装 **1.5.2 直连**包。1.5.0 / 1.5.1 会把报告页地址交给第三方图片代理，不要装。1.5.2 从调用路径、源码和 `host_permissions` 里去掉了这些代理，页地址和图片字节只允许留在 `https://kd.nsfc.cn`。请求跑在用户已经打开的结题详情页里，使用页面自己的同源 `fetch`。扩展不读 Cookie，不新增接口，也不代为通过验证。遇到 401、403 或 HTML 验证页会停下，并写明这不是最后一页。

云端只做了离线测试和构建，没有打开官网，因此不能把构建成功写成「已经下载了 22205143」。真实的单份试验由浏览器侧完成。仓库仍然没有许可证。

## 2. 报告页如何变成 PDF

下面 1–8 步是调查 1.5.1 时读到的上游路径，行号对应当时的文件。1.5.2 的当前行为以第 7 节为准。

入口在扩展的 service worker，不是网页后端。

1. 安装时注册右键菜单，只匹配 `https://kd.nsfc.cn/finalDetails*`（`src/service_worker.ts` 22–31 行）。右键或工具栏点击都进 `setTask`（34–44 行）。
2. `setTask` 从当前标签的查询参数读取 `id`。没有 `id`，或已有任务在跑，就直接返回（77 行起）。
3. `getProjectInfo` 向 `https://kd.nsfc.cn/api/baseQuery/conclusionProjectInfo/{id}` 发 POST，读取项目名、负责人、单位、摘要和关键词（`src/nsfc.ts` 89 行起）。这些字段后来写进 PDF 文档属性。
4. 页码从 1 递增。每一页调用 `getImgURL`：未命中本地缓存时，POST `https://kd.nsfc.cn/api/baseQuery/completeProjectReport`，正文是 `id` 和 `index`（`src/nsfc.ts` 30–65 行）。代码把返回 JSON 里的 `data.data.url` 拼到 `https://kd.nsfc.cn` 后面。
5. 对这个图片地址发 HEAD。HTTP 404 被当成「已经越过最后一页」：该 index 被记成结束索引，有效页是 `1 .. 结束索引-1`（`src/nsfc.ts` 67–78 行，循环在 `src/service_worker.ts` 158–191 行）。结束索引会放进 `chrome.storage.local`，键为 `img_{id}_maxpage`，默认 7 天（`src/utils.ts` 183–194 行）。缓存的是图片 URL 和结束索引，不是图片字节。
6. 图片字节不在 `getImgURL` 里下载。`getImgBlob`（`src/nsfc.ts` 14–26 行）调用 `fetchImageByProxyBatch`（`src/utils.ts` 45–71 行）。该函数把图片地址交给一组第三方图片代理，并保留原始地址；随机打乱后取 3 个并发，有一个返回就采用。体积小于 10KB 的响应会当作失败（39–41 行）。同文件 74 行起的 `fetchImageByProxy` 没有被 `getImgBlob` 调用。上游提交说明写明这是「使用图片代理服务下载文件」。这里只审阅到这一层：它会把报告页地址发到第三方主机。本轮没有运行这些请求，也没有增删代理。
7. `image-dimensions` 从字节读宽高，宽小于高则页面为纵向（`src/nsfc.ts` 19–25 行）。`AsyncPool` 最多 8 路取图（`src/service_worker.ts` 263–268 行）。
8. 全部任务结束后，`projectImg2pdf`（`src/pdf-build.ts` 10 行起）先做完整性校验，再用 `jspdf` 合成。默认空白页会删掉，每张图单独一页，尺寸等于图片像素。文件名去掉 `/ \ ? % * : | " < >`。结果是 data URI，交给 `chrome.downloads.download`，不弹出保存对话框（`src/service_worker.ts` 207–231 行）。

会话条件，按代码实测：

- 右键菜单只出现在结题详情页。工具栏点击没有同一条 URL 限制，但仍然要求地址里有 `id`。
- `extension/manifest.json` 声明了 `kd.nsfc.cn` 以及上述图片代理主机的 `host_permissions`，还有 `downloads`、`storage`、`scripting` 等权限。
- 三处 `fetch` 的初始化对象都没有 `credentials` 字段（`src/nsfc.ts` 42–53、91–102 行，`src/utils.ts` 26–36 行）。代码也不读 `document.cookie`，manifest 没有 `cookies` 权限。
- 另有外部消息入口（`src/service_worker.ts` 46–54 行）。`externally_connectable` 只匹配 `https://kd.nsfc.cn/*`。它收到长度为 2 的数组时，把第一项交给 `ReportExport`。本轮没有调用它，也没有把它扩成批量接口。

推断，不是实测：

- 官方阅读器在滑块之后才能翻页，这是使用方的观察。本仓库没有滑块、验证码或会话复制代码。本轮没有打开 `kd.nsfc.cn`，所以不能证明扩展在「人已经通过滑块」之后是否还能取到 JSON。按 Fetch 的默认 `credentials: "same-origin"`，扩展源站到 `kd.nsfc.cn` 是跨源，这些请求看起来不会带上阅读器 cookie。这只是从代码形状做的推断。
- 在线站两次提交返回「上游返回非JSON响应 HTTP 503」，同样是使用方的观察，本轮没有复现。调查前的源码里没有这句中文。它更像是另一个未公开程序的错误文案，而不是这个扩展的输出。

## 3. 云端构建与离线测试

环境：Node `v22.23.4`，pnpm `10.33.4`。`package.json` 写的是 Node `>=16.18.1`。

旧锁文件不能按冻结方式安装。`pnpm install --frozen-lockfile` 报 `ERR_PNPM_OUTDATED_LOCKFILE`：锁里仍有 `@ejfkdev/async-pool@^1.0.0`，而 `package.json` 已经没有这个依赖，任务池在 `src/async-pool/`。本分支用普通安装刷新了锁文件，之后冻结安装可以通过。

`husky install` 已标为弃用，仓库里本来也没有钩子脚本。pnpm 10 跳过了 `core-js` 和 `esbuild` 的依赖构建脚本。在这个前提下，测试和 rspack 构建仍然成功，所以这次构建不依赖那两个脚本。

`pnpm exec tsc --noEmit` 对 `src/` 没有报错。其余报错在 `node_modules` 里 rspack 自带的类型（`yargs`、`graceful-fs`、`webpack-dev-middleware`），因为 `tsconfig.json` 把 `rspack.config.ts` 算进编译且没有 `skipLibCheck`。这次没有改这份配置。

离线测试命令是 `pnpm test`。1.5.2 这一轮：13 项全部通过，0 失败。测试不访问 `kd.nsfc.cn`。除了原来的非 JSON、缺页拒绝和内存 PNG 合成 PDF，还检查：其他主机的图片地址会被拒绝、HTTP 404 才是缺页、403 与 503 不会被当成末页、清单声明 `thirdPartyImageProxy: false`，以及源码和 manifest 不再出现第三方代理主机名。构建后的 `dist/` 也检索过，没有这些主机名。这不是报告下载。

## 4. 能不能自部署网站

不能。缺的不是某几个环境变量，而是整个站点程序：

- 没有 HTML 应用、路由、服务端入口、Dockerfile 或进程管理配置。
- `express` 只出现在 rspack 开发服务器的传递依赖里，没有被扩展源码引用。
- `package.json` 只有 `build` 和本分支新增的 `test`，没有 `start`。
- `lodash` 在依赖里，`src/` 没有引用它。
- 在线站的 503 文案不在本仓库。即使把扩展托管到某台机器，也得不到 `nsfc.ejfkdev.com` 那个提交框。

本地使用只到这一步：解压 **1.5.2** ZIP，在 `chrome://extensions` 打开开发者模式，选择含 `manifest.json` 的目录。1.5.2 不再声明第三方图片主机权限。本环境没有把扩展装进浏览器。

## 5. 对研究语料意味着什么

实测后，它不适合作为语料获取流程：

- 产物是「每页一张图」的 PDF，不是正文、表格或结构化字段。项目名等只写在 PDF 属性里。
- 一次任务对应一个已经打开的详情页 `id`，没有项目清单、增量游标或本地清单。
- 1.5.1 及上游会把页图地址发到第三方主机。1.5.2 已从调用路径去掉这一步，并收窄主机权限。1.5.2 仍只产出页面图片 PDF，不是正文。
- 一次只处理当前已经打开的详情页，没有项目清单，也删掉了外部消息入口，避免页面把别的 id 推给扩展。
- 页不齐时不写 PDF。只有图片 HTTP 404 才表示没有下一页。
- 没有软件许可证。报告正文另有官方站点自己的使用条件。本仓库没有授予再分发或建库的权利。

1.5.2 会额外下载一份 `项目名.nsfc-export.json`。里面有来源页、页数、每页字节数和 SHA256，并写明 `thirdPartyImageProxy: false`。它不含 Cookie，也不含图片 URL。这仍然不是语料库。在有明确许可之前，不要把 PDF 或报告文本放进公共语料目录。官网是否接受当前页里的这次读取，要由浏览器侧的单份试验确认，不能从离线测试推断。

## 6. 本分支的小改动

版本从 1.5.0 改为 1.5.1，用来和上游扩展包区分。行为只收紧失败路径：

- 项目信息和页地址接口如果不是 JSON，错误变为「上游返回非JSON响应 HTTP {状态}（内容类型）」。HTTP 不成功、或 JSON 里没有图片路径，也会带上状态码，不再静默改用文件名 `projectName`。
- 连续 3 次取页地址失败后停止。原先 `catch` 会把页码减一并无期限重试，错误内容到不了界面。
- 图片任务的重试次数用尽后不再调用 `retry()`。原回调在次数为 0 时仍会进入 `AsyncPool` 的失败分支，那个分支会再次调用完成回调。
- 合成前要求结束索引不小于 2，且 `1 .. 结束索引-1` 每一页都有字节、宽度和高度。否则抛出「已中止，未生成PDF」。
- 浏览器下载回调如果没有得到下载 id，或运行时留下错误信息，通知标题改为「导出失败」。原先在调用下载后就显示「导出完成」。

对应代码：`src/report-check.ts`、`src/pdf-build.ts`、`src/nsfc.ts`、`src/service_worker.ts`、`test/report-check.test.ts`。

本分支只向用户 fork 开了 pull request：<https://github.com/yimmy23/NsfcReportExport/pull/1>。1.5.1 是当时的诊断包，不要再安装。

## 7. 1.5.2 直连：给浏览器侧的单份试验

当前代码只在用户已经打开、并且地址通过 `isFinalDetailsUrl` 的 `https://kd.nsfc.cn/finalDetails?id=...` 标签里导出。工具栏和右键都走这个检查。外部消息入口和 `externally_connectable` 已去掉。主机权限只剩 `https://kd.nsfc.cn/*`。

读取方式：`chrome.scripting.executeScript` 的 `world: "MAIN"` 把既有的项目信息、页地址和图片请求放进这个标签页，`credentials` 为 `same-origin`。这是为了让浏览器按普通同源请求带上用户自己已经完成验证后的会话，扩展进程不复制 Cookie，也不把 URL 拼到其他源站。若返回的图片地址不是 `https://kd.nsfc.cn`，直接拒绝。

页与页之间间隔 1500ms，同一时刻只有一路。连续 3 次可重试错误后停止。401、403 和 `text/html` 立即停止，文案写明扩展不会代为通过验证，并且这不是最后一页。图片响应只有 HTTP 404 才结束页码。网络错误、5xx 和其他状态不会被记成末页，也不会写出半份 PDF。缺页、空字节或没有宽高时仍然拒绝生成 PDF。

本环境没有安装扩展，也没有打开 22205143。下面的步骤留给浏览器侧。成功与否以那边的日志和两个下载文件为准。

### 加载

1. 使用文件名含 `1.5.2-direct` 的 ZIP。不要用 1.5.1 或更早的包。
2. 解压后，根目录必须直接有 `manifest.json`，旁边是 `service_worker.js`、`images/` 和 `libs/`。不要多套一层目录。
3. 打开 `chrome://extensions`，打开开发者模式，选择「加载已解压的扩展程序」，选中该目录。
4. 卡片名称必须是「国自然结题报告下载 直连」，版本 `1.5.2`。名称仍是「国自然结题报告下载」且版本是 1.5.0 或 1.5.1 时，装错了包，先移除再加载 1.5.2。

### 从已打开的官网页导出

1. 由操作者自己打开这一份结题详情，并在官网页面上完成官网要求的验证，直到阅读器能翻页。不要关闭这个标签。
2. 在这个标签上点击扩展图标，或右键「下载结题报告」。不要从别的网站点图标。
3. 页面底部会出现扩展自己的提示。失败时提示原文就是结论，不要把它理解成「再多试几次就会绕过」。

### 怎样核对，以及失败时回传什么

成功时，浏览器默认下载目录里应有两个文件：`项目名.pdf`，以及 `项目名.nsfc-export.json`。打开 JSON，核对：

- `extensionVersion` 为 `1.5.2`
- `thirdPartyImageProxy` 为 `false`
- `officialOrigin` 为 `https://kd.nsfc.cn`
- `sourcePage` 是刚才那个 finalDetails 地址
- `pageCount` 与 PDF 页数一致，`pages[].sha256` 每页一条

PDF 文档属性的创建者应为 `NsfcReportExport/1.5.2 direct`。

失败时不要猜测已经下完。请回传：

1. 页面提示的完整文字。
2. `chrome://extensions` 里该扩展的「服务工件」或「Service worker」→「检查视图」→ Console 中以 `NsfcReportExport/1.5.2` 开头的行。这些行只有阶段、页码、HTTP 状态、字节数和 SHA256，不应有 Cookie。
3. 扩展卡片上的名称和版本号。

不要回传 Cookie、请求头或整页 HTML。若提示里是 HTTP 403、验证页，或写着「不是最后一页」，这就是停止，不是端到端成功。
